# 最新地址表版最小闭环检测执行计划与进度

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Fake 最小闭环已验证的基础上，先同步最新地址表，再准备真实 PLC 与 GDM-9060 万用表联调。

**Architecture:** 保持当前 WPF/MVVM 小项目结构，不新增第二套 PLC 信号监听服务。继续由 `TestPageViewModel` 维护 UI 状态和启动条件，由 `InspectionEngine` 编排检测闭环，由 `IPlcDevice` / `IMultimeterDevice` 隔离 Fake 与真实设备。

**Tech Stack:** C#、WPF、CommunityToolkit.Mvvm、Microsoft.Extensions.Hosting、Serilog、Modbus TCP、SCPI over TCP、CSV UTF-8 BOM 存储。

## 3. 最新 PLC 信号协议

| 地址 | 方向 | 最新语义 | 执行计划处理 |
|---|---|---|---|
| `DT120` | PLC 写，上位机读/待确认清 | 启动请求 | 上位机读到 1 后启动前检查；是否清 0 待联调确认。 |
| `DT121` | PLC/上位机读写 | 复位 | 上位机复位后清断点、清输出，并清 `DT121=0`。 |
| `DT122` | PLC 写，上位机读 | 停止/暂停 | 暂停当前检测，保留内存断点。 |
| `DT123` | PLC 写，上位机读 | 急停 | 中止检测，禁止直接续作，必须复位后重新启动。 |
| `DT234` | 上位机写，PLC 读 | 上位机允许开始检测 | 启动前检查通过后写 1；结束/复位清 0。 |
| `DT302` | PLC 写，上位机读 | 当前测试点继电器动作完成 | 上位机等待 1 后才读取万用表；超时整轮中止。 |
| `DT303` | PLC 写，上位机读 | 报警解除 | 用于急停/报警解除 UI，清零规则待联调确认。 |
| `DT304` | 上位机写，PLC 读 | 产品 OK | 全部 OK 写 1，否则写 0。 |
| `DT305` | 上位机写，PLC 读 | 产品 NG | 任意 NG 或异常判定 NG 写 1，否则写 0。 |
| `DT130~DT185` | 上位机写，PLC 读 | 每脚独立脚选择/极性选择 | 按最新地址表逐项写入，复位/结束/单项完成后清 0。 |

不应负责：

- 弹窗。

- [ ] **Step 6: 半实物阶段增加 DT302 临时旁路开关**

背景：

```text
2026-07-03 真实 PLC 和万用表已经可以连接电脑。
当前半实物阶段没有实际夹具、继电器闭合机构和针脚回路。
上位机写入 A1-A2 后，PLC 无法真实完成引脚闭合动作，因此 DT302 不会按正式整机流程置 1。
日志证据：
14:22:58 上位机写入 A1(DT130=1,DT131=0)、A2(DT132=1,DT133=1)。
14:23:02 等待 DT302=1 超时，检测停在第一个测试项。
```

目标：

```text
UseFakeInspectionHardware=false，仍然注册真实 Fp0hPlcDevice 和真实 GwInstekGDM9060Driver。
上位机仍真实写 PLC：DT234、DT130~DT185、DT304/DT305、清 DT302 等保持真实通信。
仅在“等待当前测试点继电器动作完成”这一处，允许开发配置临时跳过 DT302=1。
跳过后继续执行：切换万用表模式 -> READ? -> 判定 OPEN/SHORT 或电阻值 -> 进入下一项。
```

推荐配置：

```json
{
  "Hardware": {
    "UseFakeInspectionHardware": false,
    "BypassRelayActionCompletedForSemiPhysicalTest": true
  }
}
```

实现要求：

```text
1. 字段只放在 appsettings.Development.json，不写入 appsettings.json。
2. 默认值必须是 false。没有该字段时必须走正式 DT302 等待流程。
3. 不修改 Modbus 层、不伪造 PLC 读取返回值、不让 Fp0hPlcDevice 返回假的 DT302=1。
4. 旁路只放在 InspectionEngine 检测流程层：
   - 写完当前测试点引脚后；
   - 如果 BypassRelayActionCompletedForSemiPhysicalTest=true，则不调用或不阻塞 WaitRelaySwitchCompletedAsync；
   - 写 Warning 审计日志，明确记录“半实物临时旁路 DT302，正式整机联调必须关闭”。
5. 代码注释必须写清楚：
   - 这是无夹具/无继电器反馈阶段的临时联调开关；
   - 正式整机联调和出厂版本必须关闭；
   - 关闭后仍以 DT302=1 作为读取万用表前置条件。
6. TestPageViewModel 启动检测前把该配置传入 InspectionConfig。
7. 运行界面可在启动日志中提示：
   - “半实物调试：已启用 DT302 临时旁路”
   - 防止操作员误以为已经完成真实继电器闭合验证。
```

不采用的方案：

```text
不建议在 Fp0hPlcDevice 或 Modbus 层把 DT302 读取值强行改成 1。
原因：会污染 PLC 通信层，使日志和调试工具看到的 PLC 状态不可信。
半实物旁路应该只影响检测流程的等待策略，不改变真实 PLC 通信结果。
```

配套修复：

```text
1. 异常/中止结果弹窗：
   - TestPageViewModel.RunInspectionAsync 必须处理 InspectionEngine 返回的 InspectionResult。
   - 如果 IsAborted=true 或 ErrorMessage 非空，要弹窗提示用户。
   - 例如：检测中止：等待 DT302 = 1 超时。请检查 PLC 是否已完成继电器动作并写入 DT302=1。

2. InspectionCompleted 事件补齐：
   - InspectionEngine 中止路径也应能通知 UI，或 RunInspectionAsync 返回结果后由 ViewModel 兜底提示。
   - 避免只写日志、不弹窗，现场操作员看不到异常原因。

3. PLC 读取成功日志降噪：
   - TcpClientPLCMotionService.ExecuteReadOperationAsync 成功读取时不要每次 Info 级别输出“读取操作成功”。
```
