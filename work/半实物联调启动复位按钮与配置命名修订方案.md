# 半实物联调启动复位按钮与配置命名修订 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在半实物联调阶段恢复非 Fake 模式下可用的 `启动(DT120)`、`复位(DT121)`入口，同时把临时联调配置限定在 `appsettings.Development.json`，避免真实设备正式运行时误带开发配置。

**Architecture:** Fake、半实物、真实运行三种模式必须分清：Fake 走 `FakeInspectionHardware`；半实物使用真实 PLC 和真实万用表，但允许上位机临时写 `DT120/DT121` 模拟现场按钮；真实模式不显示模拟启动入口，启动由 PLC 或实体按钮触发。配置拆成 `SemiPhysicalDebug` 和 `SkipDt302Wait` 两个独立开关，分别控制“半实物按钮入口”和“是否跳过 DT302 等待”。

**Tech Stack:** C#、WPF、MVVM、CommunityToolkit.Mvvm、Microsoft.Extensions.Configuration、Modbus TCP、Serilog、MSBuild。

---

## 1. 背景与结论

之前为了“非 Fake 模式隐藏调试按钮”，运行页隐藏了 `开始检测(Fake)`。这个方向对正式运行是对的，但当前处于半实物联调阶段：

```text
PLC、万用表使用真实设备；
现场启动按钮链路可能还没完整接入；
如果完全隐藏启动入口，就无法模拟 DT120=1，也无法启动真实检测流程。
```

不能把 `开始检测(Fake)` 原样放回非 Fake 模式，原因：

```text
StartFakeMinimalInspectionCommand 是直接调用 RunInspectionAsync。
它绕过 PLC 启动信号链路。
半实物联调应该验证真实路径：
上位机临时写 DT120=1 -> PLC 轮询读到启动 -> HandlePlcStartRequest -> RunInspectionAsync。
```

所以本方案新增半实物专用入口：

```text
启动(DT120)：仅半实物非 Fake 模式显示，用于临时模拟启动信号。
复位(DT121)：非 Fake 模式显示，用于当前现场临时复位入口。
终了：保持现有逻辑。
```

同时修正配置落点：

```text
UseFakeInspectionHardware、SemiPhysicalDebug、SkipDt302Wait 都只放 appsettings.Development.json。
appsettings.json 不写这些临时硬件开关。
正式真实设备运行包不携带 appsettings.Development.json。
```

## 2. 配置语义

### 2.1 配置名称

废弃旧配置名：

```text
Hardware:BypassRelayActionCompletedForSemiPhysicalTest
```

废弃原因：

```text
名字太长。
不容易第一眼识别。
同时混入“半实物联调”和“跳过 DT302 等待”两个含义。
```

替换为：

```json
{
  "Hardware": {
    "UseFakeInspectionHardware": false,
    "SemiPhysicalDebug": true,
    "SkipDt302Wait": true
  }
}
```

### 2.2 三个开关的含义

| 配置 | 含义 | 默认值 | 放置位置 | 用途 |
|---|---|---:|---|---|
| `Hardware:UseFakeInspectionHardware` | 是否启用 Fake 硬件 | `false` | `appsettings.Development.json` | `true` 时注册 Fake PLC 和 Fake 万用表 |
| `Hardware:SemiPhysicalDebug` | 半实物联调入口开关 | `false` | `appsettings.Development.json` | 非 Fake 时是否显示 `启动(DT120)` |
| `Hardware:SkipDt302Wait` | 是否跳过 `DT302` 等待 | `false` | `appsettings.Development.json` | 无夹具或 DT302 反馈未接通时，临时绕过继电器完成等待 |

关键边界：

```text
SemiPhysicalDebug 只控制 UI 入口，不改变检测流程。
SkipDt302Wait 只控制检测流程是否等待 DT302，不控制按钮显示。
UseFakeInspectionHardware 控制 DI 注册 Fake 还是真实硬件。
```

### 2.3 旧配置兼容

保留一轮兼容：

```text
如果 Hardware:SkipDt302Wait=false 或不存在，
但 Hardware:BypassRelayActionCompletedForSemiPhysicalTest=true，
则本轮仍按 SkipDt302Wait=true 生效，并输出 Warning。
```

兼容日志：

```text
[运行页][配置兼容] 旧配置 Hardware:BypassRelayActionCompletedForSemiPhysicalTest 已废弃，请改用 Hardware:SkipDt302Wait。
```

```text

点击 复位(DT121) -> 上位机临时写 DT121=1 -> PLC 轮询进入现有复位流程。
```

```text
SkipDt302Wait=true 时，检测流程会跳过 DT302 等待。
如果现场 DT302 已经接通，可以把 SkipDt302Wait 改为 false，只保留 SemiPhysicalDebug=true。
```

```text

appsettings.json 不写 Hardware:UseFakeInspectionHardware。
```

等效默认值：

```text

```

设备：

```text
IPlcDevice -> Fp0hPlcDevice
IMultimeterDevice -> GwInstekGDM9060Driver
```

UI：

```text
显示：
复位(DT121)
终了

不显示：
启动(DT120)
开始检测(Fake)
停止(DT122)
急停(DT123)

```

触发：

```text
启动由真实 PLC 或现场实体按钮写 DT120=1。
上位机只轮询读取 PLC 启动信号，不主动模拟启动。
DT302 必须按真实反馈等待，不能跳过。
```

备注：

```text
复位(DT121) 当前按现场要求保留在非 Fake 模式。
该按钮仍然要带 Warning 审计日志，标明是上位机写 PLC 复位请求。
如果后续电气确认复位也必须只由实体按钮触发，再删除该入口。
```

## 4. 配置文件与输出目录策略

### 4.1 appsettings.json

`appsettings.json` 只保留正式运行也需要的通用配置，例如数据库、日志、CSV、方案存储。

不得新增：

```json
{
  "Hardware": {
    "UseFakeInspectionHardware": true,
    "SemiPhysicalDebug": true,
    "SkipDt302Wait": true
  }
}
```

原因：

```text
appsettings.json 会进入正式输出目录。
临时硬件开关一旦进入正式配置，现场很容易误启 Fake 或误跳过 DT302。
```

### 4.2 appsettings.Development.json

开发和半实物联调用：

```json
{
  "Hardware": {
    "UseFakeInspectionHardware": false,
    "SemiPhysicalDebug": true,
    "SkipDt302Wait": true
  }
}
```

Fake 纯软件测试时改为：

```json
{
  "Hardware": {
    "UseFakeInspectionHardware": true,
    "SemiPhysicalDebug": false,
    "SkipDt302Wait": false
  }
}
```

真实整机联调前改为：

```json
{
  "Hardware": {
    "UseFakeInspectionHardware": false,
    "SemiPhysicalDebug": false,
    "SkipDt302Wait": false
  }
}
```

更严格的真实发布要求：

```text
Release 或正式发布输出目录不复制 appsettings.Development.json。
Program.cs 中 AddJsonFile("appsettings.Development.json", optional: true) 可以保留。
文件不存在时会静默跳过。
```

### 4.3 .csproj 输出控制

当前项目文件存在风险：

```xml
<None Update="appsettings.Development.json">
  <CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory>
</None>
```

它会把 `appsettings.Development.json` 复制到输出目录，不满足“真实设备运行不携带 Development 配置”的要求。

建议改为 Debug 可复制、Release/Publish 不复制：

```xml
<None Update="appsettings.Development.json">
  <CopyToOutputDirectory Condition="'$(Configuration)' == 'Debug'">PreserveNewest</CopyToOutputDirectory>
  <CopyToOutputDirectory Condition="'$(Configuration)' != 'Debug'">Never</CopyToOutputDirectory>
  <CopyToPublishDirectory>Never</CopyToPublishDirectory>
</None>
```

验收时必须检查：

```text
bin/Release/.../appsettings.Development.json 不存在。
publish 输出目录 appsettings.Development.json 不存在。
```

如果输出目录已有旧文件，正式验证前需要清理输出目录或重新发布，避免旧文件残留造成误判。

## 5. 实现设计

### 5.1 Program.cs

保留现有可选加载：

```csharp
config.AddJsonFile("appsettings.Development.json", optional: true, reloadOnChange: true);
```

原因：

```text
开发和半实物联调时，文件存在就加载。
真实发布时，文件不在输出目录，optional: true 会静默跳过。
不需要在代码里强行判断 Debug/Release，输出目录策略交给 .csproj 控制。
```

### 5.2 InspectionConfig

新增短属性，保留旧属性一轮兼容：

```csharp
public sealed class InspectionConfig
{
    public int RelaySwitchTimeoutMs { get; set; } = 5000;
    public bool SkipDt302Wait { get; set; }

    // 兼容旧配置名：下一轮清理时删除。
    public bool BypassRelayActionCompletedForSemiPhysicalTest { get; set; }
}
```

`InspectionEngine` 内只使用新属性：

```csharp
if (_config.SkipDt302Wait)
{
    _logger.Warning(
        "[检测流程][审计][{INS}] 半实物临时旁路 DT302：点位 {Name} 已跳过继电器动作完成等待。正式整机联调必须关闭 Hardware:SkipDt302Wait。",
        inspectionId,
        testPoint.Name);
}
else
{
    // 保持现有 WaitRelaySwitchCompletedAsync 逻辑。
}
```

### 5.3 TestPageViewModel 配置读取

读取时合并新旧配置：

```csharp
bool skipDt302Wait = _configuration.GetValue<bool>("Hardware:SkipDt302Wait");
bool legacySkipDt302Wait = _configuration.GetValue<bool>("Hardware:BypassRelayActionCompletedForSemiPhysicalTest");

var inspectionConfig = new InspectionConfig
{
    RelaySwitchTimeoutMs = _configuration.GetValue<int?>("Hardware:RelaySwitchTimeoutMs") ?? 5000,
    SkipDt302Wait = skipDt302Wait || legacySkipDt302Wait,
    BypassRelayActionCompletedForSemiPhysicalTest = legacySkipDt302Wait
};

if (legacySkipDt302Wait)
{
    _logger.Warning("[运行页][配置兼容] 旧配置 Hardware:BypassRelayActionCompletedForSemiPhysicalTest 已废弃，请改用 Hardware:SkipDt302Wait。");
}
```

增加 UI 可见性属性：

```csharp
public bool IsFakeMode => _plcDevice is Devices.Fakes.FakeInspectionHardware;

public bool IsSemiPhysicalDebugMode =>
    !IsFakeMode && _configuration.GetValue<bool>("Hardware:SemiPhysicalDebug");

public bool IsRealModeResetVisible => !IsFakeMode;
```

### 5.4 IPlcDevice

新增半实物/现场临时写入入口：

```csharp
Task<PlcOperationResult> RequestStartAsync(CancellationToken ct = default);
Task<PlcOperationResult> RequestResetAsync(CancellationToken ct = default);
```

说明：

```text
RequestStartAsync：写 DT120=1。
RequestResetAsync：写 DT121=1。
这两个方法只表达“请求信号写入”，不直接调用检测引擎，不绕过 PLC 轮询链路。
```

### 5.5 Fp0hPlcDevice

真实 PLC 实现：

```csharp
public async Task<PlcOperationResult> RequestStartAsync(CancellationToken ct = default)
{
    _logger.Warning("[半实物联调][审计] 上位机临时写入 DT120=1，模拟 PLC 启动请求。正式整机联调后删除该入口。");
    return await WriteSingleRegisterAsync(PlcAddressMap.StartSignal, 1, ct);
}

public async Task<PlcOperationResult> RequestResetAsync(CancellationToken ct = default)
{
    _logger.Warning("[半实物联调][审计] 上位机写入 DT121=1，发起复位请求。若后续改为实体按钮复位，应删除该入口。");
    return await WriteSingleRegisterAsync(PlcAddressMap.ResetSignal, 1, ct);
}
```

实际项目中如果写寄存器方法名不是 `WriteSingleRegisterAsync`，按当前 `Fp0hPlcDevice` 内已有写 DT120/DT121 的封装替换，不新增第二套 Modbus 客户端。

### 5.6 FakeInspectionHardware

Fake 实现同样实现接口，保持编译一致：

```csharp
public Task<PlcOperationResult> RequestStartAsync(CancellationToken ct = default)
{
    SetRegister(PlcAddressMap.StartSignal, 1);
    _logger.Warning("[Fake][审计] 已写入 DT120=1。");
    return Task.FromResult(PlcOperationResult.Success());
}

public Task<PlcOperationResult> RequestResetAsync(CancellationToken ct = default)
{
    SetRegister(PlcAddressMap.ResetSignal, 1);
    _logger.Warning("[Fake][审计] 已写入 DT121=1。");
    return Task.FromResult(PlcOperationResult.Success());
}
```

实际项目中如果 Fake 内部不是 `SetRegister`，用现有 Fake 寄存器写入方式替换。

### 5.7 TestPageViewModel 命令

新增非 Fake 半实物命令：

```csharp
[RelayCommand]
private async Task TriggerPlcStartAsync()
{
    // 半实物联调临时入口：真实 PLC 接入但现场启动按钮链路未完整联通时，
    // 由上位机临时写 DT120=1 触发现有 PLC 轮询启动流程。
    // 正式整机联调后删除该按钮和命令，启动应由 PLC 或实体按钮触发。
    var result = await _plcDevice.RequestStartAsync(CancellationToken.None);

    AddLog(result.IsSuccess
        ? "[半实物联调] 已写入 DT120=1（启动信号）"
        : $"[半实物联调] 写入 DT120=1 失败：{result.Message}");
}

[RelayCommand]
private async Task TriggerSemiPhysicalResetAsync()
{
    // 半实物/现场临时入口：真实 PLC 接入但需要上位机发起复位请求时，
    // 由上位机写 DT121=1 触发现有 PLC 轮询复位流程。
    // 如果后续复位改为只由实体按钮触发，应删除该按钮和命令。
    var result = await _plcDevice.RequestResetAsync(CancellationToken.None);

    AddLog(result.IsSuccess
        ? "[半实物联调] 已写入 DT121=1（复位信号）"
        : $"[半实物联调] 写入 DT121=1 失败：{result.Message}");
}
```

## 7. 验收标准

```text
1. appsettings.json 不包含 UseFakeInspectionHardware、SemiPhysicalDebug、SkipDt302Wait。
2. appsettings.Development.json 包含半实物/开发用硬件开关。
3. Release/Publish 输出目录不包含 appsettings.Development.json。
4. Fake 模式显示 Fake 调试工具，并通过开始检测(Fake)触发。
5. 半实物非 Fake 模式显示启动(DT120)、复位(DT121)、终了。
6. 半实物启动(DT120)只写 PLC 信号，不直接调用 RunInspectionAsync。
7. 真实模式不显示启动(DT120)，启动由 PLC 或实体按钮触发。
8. SkipDt302Wait=false 时必须等待 DT302，不允许绕过真实继电器反馈。
9. SkipDt302Wait=true 时日志必须有 Warning 审计信息。
10. 旧配置 BypassRelayActionCompletedForSemiPhysicalTest 仅一轮兼容，并输出废弃提醒。
```

## 8. 不采用的方案

### 不采用：把 `开始检测(Fake)` 显示到非 Fake 模式

原因：

```text
该按钮绕过 PLC DT120 启动链路，不适合半实物联调。
半实物联调应该验证真实启动路径，而不是直接调用检测引擎。
```

### 不采用：继续沿用 `BypassRelayActionCompletedForSemiPhysicalTest`

原因：

```text
名字太长，现场排查时不容易第一眼识别。
它同时表达“半实物”和“跳过 DT302”，语义混在一起。
拆成 SemiPhysicalDebug 和 SkipDt302Wait 更直接。
```

### 不采用：只用一个 `SemiPhysicalDebug` 控制所有行为

原因：

```text
是否显示半实物按钮，和是否跳过 DT302 等待，是两个不同决策。
有些联调阶段可能需要显示启动/复位按钮，但不跳过 DT302。
也可能不显示按钮，但临时跳过 DT302 做自动联调。
拆开更清楚。
```

### 不采用：在 Program.cs 中按 Debug/Release 判断是否加载 Development 配置

原因：

```text
Program.cs 继续 optional 加载更简单。
真实发布是否携带 appsettings.Development.json 应由 .csproj 输出规则和发布流程保证。
文件不存在时 optional: true 会静默跳过。
```
