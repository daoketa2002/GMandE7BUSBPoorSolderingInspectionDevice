# 复位后 DT120 残留导致重新启动修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复半实物/真实模式下点击复位后，因 `DT120` 启动请求残留导致运行页再次启动新一轮检测的问题。

**Architecture:** 复位属于安全收口路径，必须同时释放本轮启动握手、PLC 输出、继电器完成标志和上位机内部运行标志。本方案只改 `TestPageViewModel` 的统一复位流程和启动入口保护，不新增 PLC 监控服务，不改设备接口，不把逻辑做成半实物专用分支。

**Tech Stack:** C#、WPF、MVVM、CommunityToolkit.Mvvm、Serilog、Modbus TCP、现有 `IPlcDevice` 抽象。

---

## 1. 问题现象

半实物联调时，点击运行页 `复位(DT121)` 后，界面和日志显示复位流程完成，但万用表仍有反应，看起来像检测仍在执行。

现场日志关键片段：

```text
2026-07-04 15:54:32.888 [INF] [TestPageViewModel] [复位流程] 上位机复位操作全部完成，已清除 DT121 复位信号
2026-07-04 15:54:33.159 [WRN] [TestPageViewModel] [PLC轮询][审计] 收到 PLC 启动请求(DT120=1)
2026-07-04 15:54:33.160 [INF] [InspectionEngine] [检测流程][INS-20260704155433160] 开始检测
```

这说明复位后并不是旧检测任务继续污染 UI，而是轮询又读到了 `DT120=1`，并合法创建了新的检测任务。

---

## 2. 根因判断

上一版 `TestPageView复位后旧检测日志继续输出修复方案.md` 已解决旧检测任务晚到日志和旧回调问题：

```text
复位时递增 RunVersion。
旧检测任务返回后被丢弃。
复位期间忽略引擎 LogMessage、StepStarted、StepCompleted、InspectionCompleted。
```

但当前统一复位流程缺少清 `DT120`：

```text
已做：
StopAndWaitAsync()
ClearPinOutputsAsync()       -> 清 DT130~DT185
ClearPcReadyAsync()          -> 清 DT234
ClearResetRequestAsync()     -> 清 DT121

缺失：
ClearStartRequestAsync()     -> 清 DT120
```

同时之前 `DT120启动请求清零时机修复执行方案.md` 明确要求：

```text
正常启动通过后，DT120 保留到整轮检测完成并处理保存弹窗后再清。
复位 DT121 路径要按安全状态收口，包含清 DT120。
```

因此当前缺口是：

```text
检测中点击复位
-> 上位机停止旧检测
-> 清 DT234/DT130~DT185/DT302/DT121
-> _inspectionStarted = false
-> 但 DT120 仍为 1
-> 下一次 PLC 轮询读到 DT120=1
-> HandlePlcStartRequest()
-> 新一轮检测启动
```

## 3. 文件职责

- Modify: `ViewModels/TestPageViewModel.cs`

  - 复位后增加 `DT120` 释放保护，避免清零尚未读回前被轮询重新启动。
  - 真正接受下一轮启动时，解除旧回调屏蔽状态。

- Verify: `Services/InspectionEngine.cs`

- Verify: `Interfaces/IPlcDevice.cs`
  - 本次不改接口；直接使用现有 `ClearStartRequestAsync()`。

## 8. Task 5: 复位后增加 PLC 输入快照日志

**Files:**

- Modify: `ViewModels/TestPageViewModel.cs`

- [ ] **Step 1: 新增私有诊断方法**

在 `ExecuteResetFlowAsync()` 附近新增：

```csharp
/// <summary>
/// 复位收口后读取一次 PLC 输入快照，便于判断 DT120/DT121 是否真的释放。
/// 诊断失败不影响复位主流程。
/// </summary>
private async Task LogPlcInputsAfterResetAsync()
{
    try
    {
        var snapshot = await _plcDevice.ReadMachineInputsAsync(CancellationToken.None).ConfigureAwait(false);
        if (!snapshot.IsSuccess || snapshot.Value == null)
        {
            _logger.LogWarning("[复位流程][诊断] 复位后读取 PLC 输入快照失败：{Message}", snapshot.Message);
            return;
        }

        var inputs = snapshot.Value;
        _logger.LogWarning(
            "[复位流程][诊断] 复位后 PLC 快照：DT120={DT120}, DT121={DT121}, DT122={DT122}, DT123={DT123}, DT302={DT302}",
            inputs.IsStartRequested ? 1 : 0,
            inputs.IsResetRequested ? 1 : 0,
            inputs.IsStopRequested ? 1 : 0,
            inputs.IsEmergencyStop ? 1 : 0,
            inputs.IsRelayActionCompleted ? 1 : 0);
    }
    catch (Exception ex)
    {
        _logger.LogWarning(ex, "[复位流程][诊断] 复位后读取 PLC 输入快照异常");
    }
}
```

- [ ] **Step 2: 在清 DT121 后调用诊断方法**

在 `ExecuteResetFlowAsync()` 中 `ClearResetRequestAsync()` 后加入：

```csharp
await LogPlcInputsAfterResetAsync().ConfigureAwait(false);
```

Expected:

```text
如果 DT120 被上位机清掉后又回到 1，日志能直接显示。
如果 DT121 没清掉，也能在同一条诊断日志中看到。
```

## 11. 不采用的方案

### 不采用：复位后暂停 PLC 轮询一段固定时间

原因：

```text
固定延时只能掩盖时序问题。
如果 DT120 真的保持为 1，延时结束后仍会重新启动。
条件式等待 DT120=0 更明确。
```

### 不采用：在 InspectionEngine 内处理 DT120 清零

原因：

```text
DT120 是运行页和 PLC 启动握手语义。
InspectionEngine 只负责检测执行，不应知道保存弹窗或运行页复位收口。
```

### 不采用：新建 PLC 复位监控服务

原因：

```text
当前项目不大，PLC 输入信号 owner 已经在 TestPageViewModel 轮询中。
新增服务会形成第二个信号 owner，增加半实物联调排查难度。
```

### 不采用：只在 SemiPhysicalDebug=true 时清 DT120

原因：

```text
真实模式下实体复位同样属于本轮检测安全收口。
复位路径清 DT120 是正式协议，不是半实物调试开关。
```
