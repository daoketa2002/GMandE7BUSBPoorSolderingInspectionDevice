# 复位竞态导致旧检测回填与重复启动修复方案

## 1. 问题现象

现场测试步骤：

1. 点击 `启动(DT120)`。
2. 检测刚开始或第一项检测过程中点击 `复位(DT121)`。
3. 多次重复后，偶尔出现以下异常：
   - 复位后界面仍显示第一项 `A1-A2` 已检测、判定 `NG`。
   - 测试状态显示“异常”。
   - 日志出现“检测中止：万用表返回 ParseFailed：点位 A1-A2 判定 NG，检测中止”。
   - 偶尔点击一次复位出现两次弹窗。
   - 偶尔清空列表后，又从第一项自动开始重新检测。

## 2. 当前判断

该问题不是单纯某个寄存器没有清零，而是三个竞态叠加：

1. 旧检测任务晚到回调。
   - 检测线程读取万用表后，如果复位刚好发生，旧检测任务仍可能继续执行到 `StepCompleted`。
   - `StepCompleted` 会把第一项结果写回 UI，导致复位后又看到 `A1-A2` 的 NG/异常结果。

2. 复位流程存在重复入口。
   - `TriggerPlcResetAsync()` 写 `DT121=1` 后主动执行复位。
   - PLC 轮询也可能读到 `DT121=1`，再次进入复位。
   - 当前 `_resetSignalHandled` 不足以覆盖按钮入口和轮询入口同时竞争的场景。

3. `DT120` 启动信号按电平处理。
   - 当前逻辑看到 `DT120=1` 且 `_inspectionStarted=false` 就可能启动。
   - 复位后如果 PLC 或临时按钮链路仍返回 `DT120=1`，系统可能认为又收到启动请求，从第一项重新开始测。
   - 复位后必须等待 `DT120=0`，然后下一次 `0 -> 1` 上升沿才允许启动。

## 3. 修复目标

修复后必须满足：

1. 复位期间旧检测任务不能再回填任何检测结果、判定、日志或弹窗。
2. 点击一次复位，只出现一次复位完成弹窗。
3. 复位后不自动重新开始检测。
4. 复位后必须等待用户再次按下启动按钮。
5. 再次启动必须从方案第一项开始。
6. Fake、半实物、真实模式共用同一套复位收口规则。

## 4. 推荐改动方案

### 4.1 增加复位流程防重入锁

在 `TestPageViewModel` 增加字段：

```csharp
private bool _resetFlowInProgress;
```

用途：

- 表示完整复位流程正在执行。
- 按钮入口和 PLC 轮询入口都必须先检查该标志。
- 如果 `_resetFlowInProgress=true`，直接记录 Warning 日志并忽略本次重复复位请求。

建议规则：

```text
进入 ExecuteResetFlowAsync 前：
if (_resetFlowInProgress) return;
_resetFlowInProgress = true;

复位流程 finally：
_resetFlowInProgress = false;
```

注意：

- `_resetSignalHandled` 仍保留，用于处理 `DT121` 电平保持时的边沿防重复。
- `_resetFlowInProgress` 用于防止按钮入口、Fake 入口、PLC 轮询入口并发进入同一个复位流程。

### 4.2 修正复位按钮调用方式

当前按钮入口中存在类似写法：

```csharp
await Application.Current.Dispatcher.InvokeAsync(async () =>
{
    await ExecuteResetFlowAsync();
});
```

这种写法容易让外层流程和内部异步复位流程的完成时机不清晰，增加竞态风险。

建议改为：

```csharp
await ExecuteResetFlowAsync();
```

要求：

- `ExecuteResetFlowAsync()` 内部自己负责 UI 线程更新。
- 按钮入口只负责写 `DT121=1`、读回确认、然后等待完整复位流程结束。
- Fake 复位按钮和半实物/真实复位按钮都按这个规则改。

### 4.3 复位一开始就屏蔽旧检测回调

进入复位流程后第一时间执行：

```csharp
_ignoreInspectionCallbacksUntilNextStart = true;
_isResetting = true;
Interlocked.Increment(ref _inspectionRunVersion);
```

并保持以下回调防护：

- `OnStepStarted`
- `OnStepCompleted`
- `OnInspectionCompleted`
- `OnInspectionLogMessage`
- `RunInspectionAsync` 返回后的结果处理

这些位置只要发现以下任一条件为真，就直接丢弃旧结果：

```text
_ignoreInspectionCallbacksUntilNextStart == true
_isResetting == true
runVersion != _inspectionRunVersion
```

### 4.4 检测引擎增加取消检查点

在 `InspectionEngine.RunInspectionAsync()` 中，以下关键位置必须检查取消：

1. 写完当前测试点后。
2. 等待 `DT302` 或跳过 `DT302` 后。
3. 读取万用表前。
4. 读取万用表返回后、解析前。
5. 写单项结果前。
6. 触发 `StepCompleted` 前。
7. 触发 `InspectionCompleted` 前。

重点是读取万用表后这段：

```text
ReadResistanceRawAsync 返回
-> 复位刚好发生
-> 如果不检查取消，旧检测仍会解析并写 UI
```

修复后，复位一旦触发，旧检测最多安全退出，不能再写第一项结果。

### 4.5 启动信号改为上升沿触发

在 `TestPageViewModel` 增加字段：

```csharp
private bool _startSignalHandled;
```

处理规则：

1. 当读到 `DT120=0`：
   - `_startSignalHandled=false`。
2. 当读到 `DT120=1`：
   - 如果 `_startSignalHandled=true`，说明这是保持电平，不重复启动。
   - 如果 `_startSignalHandled=false`，才允许进入启动复核。
   - 启动复核通过或拒绝后，都设置 `_startSignalHandled=true`。

复位后额外要求：

- `_waitDt120ReleaseAfterReset=true` 时，即使读到 `DT120=1` 也不启动。
- 持续尝试清 `DT120=0`。
- 只有读到 `DT120=0` 后，才解除 `_waitDt120ReleaseAfterReset`，并允许下一次启动上升沿。

### 4.6 复位后内部状态收口

复位成功后，统一设置：

```text
_inspectionStarted = false
_startupCleared = true
_startSignalHandled = true 或根据 DT120 快照决定
_ignoreInspectionCallbacksUntilNextStart = true
```

说明：

- `_ignoreInspectionCallbacksUntilNextStart` 不应在复位完成立即恢复为 false。
- 它应在下一次合法启动通过 `HandlePlcStartRequest()` 后再恢复为 false。
- 这样复位完成到下一次启动之间，所有旧检测晚到回调都会被丢弃。

## 5. 文件修改范围

预计修改以下文件：

- `ViewModels/TestPageViewModel.cs`
  - 增加 `_resetFlowInProgress`。
  - 增加 `_startSignalHandled`。
  - 修正 `TriggerPlcResetAsync()` 和 `FakeTriggerResetAsync()` 的复位调用方式。
  - 调整 `UpdateUiStateFromPlcInputsAsync()` 中 `DT120` 启动处理为上升沿触发。
  - 调整复位完成后的状态标志，避免旧回调恢复。

- `Services/InspectionEngine.cs`
  - 在读取万用表后、写单项结果前、事件回调前增加取消检查点。
  - 确保复位取消后旧检测任务不会继续触发 `StepCompleted`/`InspectionCompleted`。

## 6. 验收标准

### 6.1 启动后立刻复位

步骤：

1. 点击 `启动(DT120)`。
2. 看到第一项开始检测后立即点击 `复位(DT121)`。

期望：

- 只出现一次复位完成弹窗。
- 测试列表全部清空为未检测状态。
- 第一项不会被旧检测回填为 NG。
- 状态不是“异常”。
- 日志中可以看到旧检测被丢弃或取消，但 UI 不显示旧检测结果。

### 6.2 连续点击复位

步骤：

1. 检测过程中连续点击 `复位(DT121)` 两次或多次。

期望：

- 只执行一次复位收口。
- 只出现一次复位完成弹窗。
- 额外复位请求被 Warning 日志记录为忽略。

### 6.3 复位后不自动启动

步骤：

1. 启动检测。
2. 点击复位。
3. 不再点击启动。

期望：

- 系统保持待机或可启动状态。
- 不自动从第一项开始检测。
- 如果 `DT120` 残留为 1，日志提示“复位后仍读到 DT120=1，已忽略并再次清除”。

### 6.4 再次启动从第一项开始

步骤：

1. 启动检测。
2. 检测到第 1 项或第 2 项时复位。
3. 复位完成后再次点击启动。

期望：

- 从方案第 1 项开始。
- 不从停止断点继续。
- `InspectionEngine` 内存断点已清空。

## 7. 不采用的方案

### 不采用：只在 UI 回调里多加几个 if

原因：

- 旧检测任务仍可能写 PLC、触发弹窗或改变引擎状态。
- 只挡 UI 回调不能彻底解决旧任务晚到问题。

### 不采用：复位后立即把 `_ignoreInspectionCallbacksUntilNextStart=false`

原因：

- 复位完成后到下一次启动前，旧检测任务仍可能返回。
- 太早恢复会让旧任务重新污染 UI。

### 不采用：继续按 `DT120=1` 电平启动

原因：

- PLC 或半实物按钮可能存在电平残留。
- 复位后必须等待下一次用户启动动作，不能因为旧电平自动重测。

## 8. 下一步执行顺序

确认后按以下顺序实施：

1. 增加 `_resetFlowInProgress` 和 `_startSignalHandled`。
2. 修正复位按钮入口，取消 `Dispatcher.InvokeAsync(async () => ...)` 包装。
3. 将 `DT120` 启动改为上升沿触发。
4. 调整复位完成后的状态标志，保持旧回调屏蔽直到下一次合法启动。
5. 在 `InspectionEngine` 增加取消检查点。
6. 执行 `dotnet build`。
7. 按验收标准手工复测。
